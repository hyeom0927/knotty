## ~~P1. 도안 신뢰도 (기법 테이블 · 코수 검증)~~ ✅ 2026-08-20 완료

노트 2~6번. **Knotty의 품질을 결정하는 핵심 구간**이었습니다.

> 🔴 **선행 조건**: [DATA_MODEL.md의 SQL](DATA_MODEL.md#1-1-supabase에-적용해야-할-sql)을 Supabase에서 실행해야
> `craft_terms_pending`(미등록 기법 큐)과 `stitch_delta`(사전 기반 코수 검증)가 작동합니다.
> 실행 전에도 서비스는 정상 동작하며, 해당 기능만 조용히 비활성화됩니다.

### 1-1. 기법 테이블을 프롬프트에 주입 ✅
`craft_terms` 전체를 5분 캐싱으로 읽어(`get_craft_terms_catalog`) Pass 2 시스템 프롬프트에
**허용 약어 목록**으로 삽입합니다. 목록 밖 기법은 약어를 지어내지 말고 `instruction`에 한국어로 서술한 뒤
`unknown_terms`에 원문을 담도록 지시합니다. 카탈로그는 프롬프트 주입·기법 매칭·코수 검증이 공유합니다.

### 1-2. 신규 기법 감지 → 등록 큐 ✅
`unknown_terms` → `craft_terms_pending`에 `occurrence_count`와 함께 누적(`record_unknown_terms`).
자주 나오는 것부터 사전에 등록하면 됩니다. 테이블이 없거나 실패해도 **도안 생성은 막지 않습니다.**

### 1-3. 코수 계산 검증 ✅
노트 5번. `formula`를 직접 파싱해 코수를 합산하고 `total_stitches`와 대조합니다.

- 반복 그룹 `(sc 2, inc 1) x 4`, 매직링 시작, 기둥사슬 ↔ 기초사슬 구분을 모두 처리
- 사전에 없는 기법이 한 줄에라도 섞이면 `skipped` — **틀린 경고를 내느니 침묵**
- 불일치 시 `validation: {status, reason, expected, parsed}` 부착. **자동 교정 없음**
- 단 간 연속성 검사 포함. 틀린 단은 다음 단의 기준선에서 제외해 연쇄 오탐을 막습니다
- `craft_terms.stitch_delta`를 채우면 검증 범위가 자동으로 넓어집니다

### 1-4. 바늘 종류 제약 ✅
프롬프트에서 `코바늘`/`대바늘`만 허용하고, 서버의 `normalize_needle_type()`이 다시 보정합니다.
"니들 5mm"처럼 모호하면 `formula`의 약어 분포로 추론하며, **추론도 불가능하면 원본을 그대로 둡니다**(없는 정보를 지어내지 않음).

### 1-5. 기법 영상 링크 fallback 제거 ✅
`video_url`이 없으면 링크 대신 `-`를 표시합니다. 원본 도안 영상으로 잘못 연결되던 문제 해결.

### 2-2. 출처 블록 강화 🟡 2026-08-22 대부분 완료

- 채널명 / 영상 링크 / 채널 링크 / 썸네일 ✅
- **도안 판매 링크** ✅ — `extract_shop_links()`가 설명란에서 뽑아 **"정식 도안 구매하기" 버튼**으로 크게 배치

#### 분류를 도메인이 아니라 문구로 하는 이유

처음 계획은 도메인 화이트리스트(아이디어스·스마트스토어…)였지만, 실제 설명란 7건을 열어 보니
**같은 도메인이 도안도 팔고 실도 팔았습니다.**

```
메리노프린트 1볼 + 도안 + 동영상 패키지로 한번에 구매하기: https://banul.co.kr/shop/shopdetail.html?...
메리노프린트 실 구매 링크 :                              https://banul.co.kr/shop/shopdetail.html?...
```

주소만으로는 구분이 불가능하고, **창작자가 링크 옆에 써 둔 말이 정답**입니다.
그래서 문구로 분류하고, 버튼에도 그 문구를 그대로 보여줍니다. 우리가 "실 구매처"라고
분류명을 지어 붙이는 것보다 정확하고, 틀렸을 때도 창작자의 표현이라 덜 무례합니다.

근거가 없는 링크는 **아예 넣지 않습니다.** 인스타·블로그·음원 출처는 도메인으로 걸러내고,
"※ 이 외 도안판매 및 도안의 무단 복제, 배포…" 같은 **저작권 공지**도 제외합니다
(실제로 이게 도안 구매 링크로 잘못 잡혔습니다).

> **저장 위치**: `patterns.pattern_data.shop_links`. 별도 테이블을 만들지 않았습니다 —
> "이 도안의 링크 전부"로만 읽히고 영상당 0~5개뿐이라 join을 늘릴 이유가 없습니다.
> 설명란에서 언제든 다시 뽑을 수 있는 파생 데이터이기도 합니다.
> **링크 클릭률을 재기 시작하면**(P4) 그때 `pattern_links` 테이블로 옮기는 것이 맞습니다.
>
> `PUT`에 인증이 없으므로 **`shop_links`는 서버 저장값을 항상 우선**합니다.
> 그러지 않으면 누구나 "정식 도안 구매하기" 버튼의 주소를 바꿔치기할 수 있습니다.

### ~~2-4. 실 정보 구조화 (굵기 · 게이지)~~ ✅ 2026-08-22 완료

`materials.yarn`을 **객체 배열**로 바꿨습니다. 문자열 하나에 실 두 종이 들어가던 문제
(`"로미오실 (27번), 줄리엣실 (63번)"`)가 구조적으로 해결됩니다.

```json
"yarn": [
  { "name": "오메가", "color": "186번 귤색", "weight": "중세사",
    "amount": "50g 1볼", "gauge": null, "source": "video" }
]
```

**`source`가 이 기능의 핵심입니다.** 게이지가 다르면 완성 크기가 통째로 달라지는데,
영상에서 게이지를 말하는 경우는 드뭅니다. **AI가 그럴듯한 게이지를 지어내면 사용자는
잘못된 크기로 완성합니다.** 그래서

- 프롬프트: "말하지 않았으면 반드시 `null`", 애매하면 `inferred`
- 서버(`normalize_yarn`): 근거(`source`)가 없는데 게이지만 있으면 **`inferred`로 강등**
- 화면: `inferred`는 **(추정)** 배지, 게이지가 아예 없으면 *"영상에 언급되지 않았어요.
  완성 크기가 다를 수 있습니다"* 라고 알림

`"없음"`·`"-"`·빈 문자열은 전부 `null`로 통일합니다 — AI가 "모른다"를 여러 방식으로 적습니다.

**하위호환** — 저장된 7건은 전부 문자열이었습니다. 문자열·객체·배열 세 형태를 모두 받고,
**문자열은 쉼표로 쪼개지 않습니다.** `"오메가 (186번 귤색)"`처럼 이름 안에 쉼표가 있을 수
있어서, 쪼개면 없던 실이 생깁니다. 다음 재생성 때 자연스럽게 제 구조를 갖춥니다.

### 2-5. 실 검색 링크 (2-2의 남은 항목) ✅ 2026-08-22 완료

창작자가 링크를 안 걸어 둔 영상이 **7건 중 3건**입니다. 그럴 때 실 이름으로
네이버쇼핑 검색 링크를 만듭니다. 없는 주소를 지어낼 수는 없지만, 검색 결과는 확실히 존재합니다.

- **창작자가 건 링크가 있으면 만들지 않습니다.** 본인이 지정한 판매처가 언제나 낫습니다
- 라벨을 **"검색"으로 분리**합니다(🧶 원작자 준비물 링크 / 🔎 실 검색).
  섞으면 우리 추측이 원작자 공식 판매처처럼 보입니다
- `"빨간색 실"`처럼 상품명이 아닌 것, 괄호 안 색번호는 검색어에서 제외합니다
- 검색어를 만들 때만 쉼표로 나눕니다 — **저장된 실 구조는 건드리지 않습니다**


### 2-6. 실 사전 — 게이지 보완 ✅ 2026-08-23

**영상에는 게이지가 없습니다.** 저장된 7건의 자막(총 13만 자)과 설명란을 전수 검사한 결과
**게이지 언급이 0건**이었습니다. `gauge: null`은 추출 실패가 아니라 사실이었습니다.

그래서 실 이름으로 사전(`yarn_specs`)을 찾아 보완합니다. [docs/yarn_specs.sql](yarn_specs.sql)
실행이 선행 조건이며, 실행 전에는 이 기능만 조용히 꺼집니다.

#### 조사하면서 바뀐 설계

처음 생각은 "검색해서 게이지를 찾아 넣자"였는데, 실제로 찾아보니 두 가지가 달랐습니다.

**① 실 라벨 게이지 ≠ 그 도안의 게이지**

| | 게이지 |
|---|---|
| 메리노프린트 **실 라벨** | 20코 × 27단 |
| 같은 실로 뜬 **고양이귀 비니 도안** | 22코 × 31단 |

같은 실이라도 도안마다 다릅니다. 라벨 값을 `gauge`에 넣으면 **우리가 그토록 피하려던
"틀린 게이지로 완성 크기를 잘못 잡는" 문제를 그대로 만듭니다.**
그래서 `spec.gauge_label`이라는 다른 자리에 담고, 화면에서도 줄을 나눠
**"실 라벨 기준"** 이라고 못 박습니다.

**② 코바늘 실은 게이지를 아예 공개하지 않습니다**

롤리코튼(앵콜스)은 중량 30g±3g, 길이 60m±5m, 권장 호수 4/0~5/0호만 있고 게이지가 없습니다.
코바늘은 도안마다 게이지가 달라 라벨에 적을 수 없기 때문입니다.
그래서 사전은 게이지를 강요하지 않고, **권장 바늘 호수와 중량·길이**를 담습니다 —
"대체 실을 고르려면 굵기를 알아야 한다"는 원래 목적에는 이쪽이 오히려 맞습니다.

#### 운영

- 값은 **확인한 페이지가 있는 것만** 넣고 `source_url`을 남깁니다. 모르면 `null`입니다
- 사전에 없는 실은 로그에 남습니다: `🧵 사전에 없는 실: 퍼지퍼지 실, 신놀리 코튼`
- 자주 나오는 것부터 채워 넣으면 됩니다. `craft_terms`를 키운 방식과 같습니다
- 런타임 웹 검색은 쓰지 않습니다. 상품 페이지가 빈 콘텐츠를 반환해 스크래핑이
  불안정하고, 완성 크기를 좌우하는 값을 매번 새로 추측하게 만들 수 없습니다


## ~~P3. 탐색 · 커뮤니티~~ ✅ 2026-08-22 완료

노트 9~11번. DB 컬럼(`view_count` · `is_hidden` · `reports`)이 마이그레이션 때 이미
준비돼 있어서, 엔드포인트 3개와 화면 3개를 붙이는 작업이었습니다.

### 3-1. 최근 본 정리 ✅
localStorage에 `{id, title}`을 최대 12개. 로그인 없습니다.
결과 화면을 보고 있을 때는 접어 둡니다 — 같은 화면을 두 번 채울 이유가 없습니다.

### 3-2. 게시판 + 조회수 ✅

`GET /api/patterns?sort=recent|popular&page=&size=&q=`

- **목록에는 본문(`pattern_data`)을 싣지 않습니다.** 카드에 필요한 것만 골라 담습니다
- `is_hidden`인 도안은 제외합니다 (창작자 opt-out 요청용 — POSITIONING 원칙 ④)
- `size` 상한 48. 한 번에 전부 퍼가지 못하게 합니다
- 작품명 검색은 입력이 멈춘 뒤 300ms에 보냅니다. 글자마다 부르면 서버를 두들깁니다

> **조회수는 읽고 더해 쓰는 방식입니다.** 동시 요청이 겹치면 몇 건 샙니다.
> 정확히 세려면 Supabase에 원자적 증가 함수(RPC)가 필요한데, "요즘 유행하는 도안"을
> 고르는 데 쓰는 값이라 몇 건의 오차는 순위를 바꾸지 않습니다. 도안이 수백 건이 되고
> 순위 다툼이 생기면 그때 옮깁니다. **실패해도 조회 자체는 막지 않습니다.**

⬜ **남은 것**: "최근 7일 조회수" 기준 집계 (지금은 전체 누적), 채널명·기법 검색

### 3-3. 용어사전 ✅

`GET /api/craft-terms` + 헤더의 '용어사전' 탭. 기호 · 약어 · 한국어 · 설명 · 기법영상.
**P1에서 기법 사전을 만들어 둔 덕에 거의 공짜로 얻어졌습니다** — 도안이 이미 이 표를
기준으로 만들어지므로, 사전 화면은 같은 데이터를 다르게 보여주는 것뿐입니다.

**필터** — 전체 / 코바늘 / 대바늘 / 뜨개 용어.
'뜨개 용어'는 바늘 종류와 **다른 축**입니다. `formula`에 쓰이지 않는 항목
(배색·돗바늘 마무리처럼 코수를 만들지 않는 것)이라 `entry_type`으로 거릅니다.

#### 순서 — 한국 뜨개 기호표 관례를 따릅니다

알파벳순이나 등록순은 배우는 사람에게 아무 의미가 없습니다. 뜨개 책이 늘어놓는 순서를 씁니다.

| 무리 | 순서 |
|---|---|
| **기초** | 사슬뜨기 · 매직링 · 사슬 원형코 · 타원형 · 돗바늘 마무리 · 배색 |
| **기본 뜨기** | **기둥 높이 순** — 빼뜨기 → 짧은뜨기 → 긴뜨기 → 한길긴뜨기 → 두길 → 세길 |
| **늘리기** | 밑바탕 기법의 높이 순 — 짧은뜨기 2코·3코 → 긴뜨기 → 한길긴뜨기 → 두길긴뜨기 |
| **줄이기** | 같은 원리로 — 짧은뜨기 2코·3코 → 한길긴뜨기 2·3·4코 |
| **무늬 · 응용** | 이랑뜨기 → 걸어뜨기 → 입체무늬(퍼프·구슬·팝콘) → 가장자리(새우뜨기) |
| **대바늘** | 코잡기 → 겉·안뜨기 → 늘림(바늘비우기) → 줄임 |

**기둥 높이 순이 핵심입니다.** 짧은뜨기·긴뜨기·한길긴뜨기는 같은 계열에서 높이만 다르고,
[SYMBOLS.md](SYMBOLS.md)의 기호도 "빗금 개수 = 높이"로 그려져 있어 순서대로 보면
기호의 규칙이 저절로 읽힙니다.

목록에 없는 새 기법은 버리지 않고 제 무리의 맨 뒤(또는 '그 밖의 기법')로 보냅니다.

### 3-4. 오류 보고 ✅
