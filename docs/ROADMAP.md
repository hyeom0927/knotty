### 0-2. `channel_url` 수집 복구 ✅
`get_youtube_data_sync()`에서 `"channelId":"(UC…)"`를 파싱해 `https://www.youtube.com/channel/{id}`로 조립합니다.
실패 시 `"canonicalBaseUrl":"/@handle"`로 fallback합니다. 실제 뜨개 채널로 동작 확인 완료.

핸들(`@name`)은 변경될 수 있으므로 **불변인 channelId를 우선**합니다 — `creators.channel_url`이 중복 방지 키이기 때문입니다.
이로써 노트 1번(Creators 수집·중복 방지)이 기존 upsert 로직으로 충족되고, `patterns.creator_id`도 채워집니다.
`/api/generate` 응답에 `creators` 레코드를 포함시켜 UI가 채널명을 `creators` 기준으로 표시합니다(노트 7번 전반부).

### 0-3. 도안 수정 저장 버그 ✅
각 셀에 `data-step-path="파츠인덱스.단인덱스"` + `data-field`를 부여하고, 저장 시 `collectEdits()`가 DOM을 순회하며
`currentPatternData`에 되쓴 뒤 PUT을 보냅니다. 작품명 · 준비물(실/바늘/부자재/총단수) · 단별 4개 필드가 모두 반영됩니다.

- 바늘은 `"코바늘 (3/0호(2.3mm))"` 형태로 렌더링되므로 **마지막 괄호 기준**으로 `{type, size}`를 되돌립니다
- 부자재는 `"단수링, 돗바늘 / 총 36단"`을 `accessories[]` + `total_rows`로 분해합니다

## ~~P1. 도안 신뢰도 (기법 테이블 · 코수 검증)~~ ✅ 2026-08-20 완료

노트 2~6번. **Knotty의 품질을 결정하는 핵심 구간**이었습니다.

> 🔴 **선행 조건**: [DATA_MODEL.md의 SQL](DATA_MODEL.md#1-1-supabase에-적용해야-할-sql)을 Supabase에서 실행해야
> `craft_terms_pending`(미등록 기법 큐)과 `stitch_delta`(사전 기반 코수 검증)가 작동합니다.
> 실행 전에도 서비스는 정상 동작하며, 해당 기능만 조용히 비활성화됩니다.

### 1-1. 기법 테이블을 프롬프트에 주입 ✅
`craft_terms` 전체를 5분 캐싱으로 읽어(`get_craft_terms_catalog`) Pass 2 시스템 프롬프트에
**허용 약어 목록**으로 삽입합니다. 목록 밖 기법은 약어를 지어내지 말고 `instruction`에 한국어로 서술한 뒤
`unknown_terms`에 원문을 담도록 지시합니다. 카탈로그는 프롬프트 주입·기법 매칭·코수 검증이 공유합니다.

### 1-2. 신규 기법 감지 → 등록 큐 ✅
`unknown_terms` → `craft_terms_pending`에 `occurrence_count`와 함께 누적(`record_unknown_terms`).
자주 나오는 것부터 사전에 등록하면 됩니다. 테이블이 없거나 실패해도 **도안 생성은 막지 않습니다.**

### 1-3. 코수 계산 검증 ✅
노트 5번. `formula`를 직접 파싱해 코수를 합산하고 `total_stitches`와 대조합니다.

- 반복 그룹 `(sc 2, inc 1) x 4`, 매직링 시작, 기둥사슬 ↔ 기초사슬 구분을 모두 처리
- 사전에 없는 기법이 한 줄에라도 섞이면 `skipped` — **틀린 경고를 내느니 침묵**
- 불일치 시 `validation: {status, reason, expected, parsed}` 부착. **자동 교정 없음**
- 단 간 연속성 검사 포함. 틀린 단은 다음 단의 기준선에서 제외해 연쇄 오탐을 막습니다
- `craft_terms.stitch_delta`를 채우면 검증 범위가 자동으로 넓어집니다

### 1-4. 바늘 종류 제약 ✅
프롬프트에서 `코바늘`/`대바늘`만 허용하고, 서버의 `normalize_needle_type()`이 다시 보정합니다.
"니들 5mm"처럼 모호하면 `formula`의 약어 분포로 추론하며, **추론도 불가능하면 원본을 그대로 둡니다**(없는 정보를 지어내지 않음).

### 1-5. 기법 영상 링크 fallback 제거 ✅
`video_url`이 없으면 링크 대신 `-`를 표시합니다. 원본 도안 영상으로 잘못 연결되던 문제 해결.

## P2. 저작권 대응 & 화면 개편

노트 7~8번 + 하단 "도안을 만든다고 표현하는 게 걱정된다" 항목. 상세한 논리는 [POSITIONING.md](POSITIONING.md).

> **P2에서 가장 먼저 할 것은 2-0(단별 영상 링크)입니다.** 사용성으로도 가장 큰 개선이고,
> 저작권 대응의 핵심 장치이기도 합니다 (POSITIONING.md 원칙 ② "영상 없이는 완결되지 않게").

### 2-0. 단별 타임스탬프 → 영상 바로 재생 🔴 최우선

**Knotty를 만든 이유 그 자체입니다.** 초보자가 영상을 보다 "방금 몇 단이었지?" 하고 되감는 걸
없애는 기능이고, 동시에 결과물을 **독립 도안이 아니라 영상 내비게이션**으로 만들어 줍니다.

**지금은 완전히 죽어 있습니다.** 저장된 도안 5건 · 88단을 전수 확인한 결과
`timestamps.start`가 0보다 큰 단이 **0개**입니다.

원인은 **Pass 1 스키마에 타임스탬프 항목이 없다**는 것입니다.
자막은 `[123s] 텍스트` 형태로 들어오는데 Pass 1이 이를 버리고, Pass 2는 받은 게 없으니
`{start: 0, end: 0}`으로 채웁니다. Pass 2 프롬프트만 봐서는 눈치채기 어려운 구조였습니다.

- **Pass 1 스키마에 `start_sec` 추가** — 각 단의 뜨기가 시작되는 자막 시각(초). 모르면 `null`
- **Pass 2가 `timestamps.start`로 그대로 전달** — 새로 지어내지 말 것
- **서버 검증** — 코수 검증과 같은 철학으로, 값을 고치지 않고 이상한 것만 표시
  - 단조 증가하는가 (뒤 단의 시각이 앞 단보다 빠르면 의심)
  - 영상 길이를 넘지 않는가 (자막 마지막 타임스탬프와 대조)
  - 어긋나면 그 단의 링크만 숨김 — **틀린 시각으로 보내는 것이 링크 없는 것보다 나쁩니다**
- **UI** — 단수 셀에 ▶ 아이콘, `https://www.youtube.com/watch?v={id}&t={start}s` 로 새 탭 재생
- **PDF/PNG 내보내기에서도 링크 유지** — `enableLinks: true`가 이미 켜져 있어 그대로 살아납니다

### 2-1. 카피 전면 교체
"도안을 만들어 드립니다" → **"영상을 따라 뜨기 쉽게 정리해 드립니다"** 계열로 전환.
- 메인 카피 (`index.html:49`)
- 버튼: "도안 추출하기" → "영상 정리하기"
- 카드 푸터: "Generated by Knotty AI" → 원작자 표기 포함 문구

### 2-2. 출처 블록 강화
카드 상단을 **원작자 크레딧 영역**으로 승격합니다.
- 채널명은 `creators.channel_name` 기준으로 표시 (P0-2 완료 후)
- 영상 링크 / 채널 링크 / 썸네일 — 이미 있음
- **도안 판매 링크**: 설명란에서 판매처 URL 추출 (아이디어스, 스마트스토어, 자체몰 등 도메인 화이트리스트 방식)
- **실 구매 링크**: 설명란 링크 우선 → 없으면 `실 이름 + 채널명`으로 검색 링크 생성 (바늘이야기·앵콜스·솜솜뜨개처럼 채널 운영자가 직접 쇼핑몰을 하는 경우가 많음)

### 2-3. 유튜브 댓글용 텍스트 내보내기
노트 마지막의 홍보 아이디어이자 **가장 저렴한 유입 경로**입니다.
- "댓글용 텍스트 복사" 버튼 → 단별 요약을 plain text로 클립보드에 복사
- 말미에 `— scripted by Knotty 🧶 (링크)` 자동 삽입
- 유튜브 댓글은 서식이 없으므로 표 대신 `1단 | ch 2, dc 12 (24코)` 형태의 한 줄 포맷으로
- **2-0이 끝나면 각 줄 앞에 `19:49` 형태의 시각을 넣습니다.** 유튜브 댓글은 `분:초`를
  자동으로 재생 링크로 바꿔주므로, 댓글 자체가 목차가 되어 훨씬 유용해집니다

### 2-4. 실 정보 구조화 (굵기 · 게이지)

**게이지가 없으면 도안이 무의미합니다.** 같은 도안이라도 게이지가 다르면 완성 크기가 달라지고,
실 굵기를 모르면 대체 실을 고를 수도 없습니다. 뜨개에서 준비물은 부록이 아니라 도안의 일부입니다.

지금은 `materials.yarn`이 **문자열 하나**입니다. 저장된 5건 전부 굵기·게이지가 없습니다.

```
"오메가 (186번 귤색)"          ← 실명과 색번호만
"더 퍼스트 모헤어"
"로미오 실 (27번 - 몸통용), 줄리엣 실 (63번 - 눈용)"
```

객체로 바꿉니다.

```json
"yarn": [
  {
    "name": "오메가",
    "color": "186번 귤색",
    "weight": "중세사",             // 굵기 등급
    "amount": "50g 1볼",
    "gauge": "10×10cm = 22코 × 28단",
    "source": "video"               // video = 영상에서 언급 / inferred = 추론
  }
]
```

- **배열로 바꿉니다** — 문어 키링처럼 실을 2종 쓰는 도안이 이미 있습니다
- **`source` 필드가 핵심입니다.** 영상에 게이지가 안 나오는 경우가 대부분인데,
  **AI가 게이지를 지어내면 사용자가 잘못된 크기로 완성합니다.** 모르면 `null`로 두고,
  실 이름에서 추론한 값은 `inferred`로 표시해 화면에서 "추정"이라고 알려줍니다
- **하위호환** — 기존 5건은 문자열이므로 코드가 문자열·객체·배열 세 형태를 모두 렌더링해야 합니다
- 굵기 등급은 `craft_terms`처럼 **실 사전 테이블**로 뺄 수도 있습니다(중세사·극세사·모헤어 …).
  P4의 실 구매 링크와 연결되므로 그때 함께 검토합니다

## P3. 탐색 · 커뮤니티

노트 9~11번.

### 3-1. 내가 본 도안 (로그인 없이)
"창작자"가 아니라 **내가 검색한 링크들의 기록**입니다. localStorage에 `pattern_id` 배열을 쌓고, 목록 화면에서 일괄 조회하면 로그인 없이 구현됩니다.

### 3-2. 게시판 + 조회수
- `GET /api/patterns?sort=recent|popular&page=` 목록 엔드포인트 신설
- `patterns.view_count` 컬럼 추가, 조회 시 증가 (Supabase RPC로 원자적 증가)
- "요즘 유행하는 도안" = 최근 7일 조회수 정렬

### 3-3. 용어사전 페이지
노트 12번. `craft_terms` 테이블을 그대로 보여주는 목록 화면(영문 약어 / 한국어 / 참고 영상 / 검색).
기법 테이블이 곧 사전이므로 **P1이 끝나면 거의 공짜로 얻어지는 기능**입니다.

### 3-4. 오류 보고
노트 11번. 도안 30개 규모라면 무거운 도구가 필요 없습니다.
카드 하단에 "이 도안 이상해요" 버튼 → `{ pattern_id, step, message }`를 `reports` 테이블에 적재. 끝.
