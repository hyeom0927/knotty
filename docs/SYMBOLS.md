# 도안 기호 아이콘 규칙

`symbols/` 폴더의 SVG 아이콘을 그리고 관리하는 규칙입니다.
좌표는 전부 [`symbols/generate.py`](../symbols/generate.py) 한 곳에 모여 있고, 실행하면 SVG가 다시 생성됩니다.

```bash
python3 symbols/generate.py    # 28개 아이콘 + preview.svg 재생성
```

전체 모양은 [`symbols/preview.svg`](../symbols/preview.svg)를 브라우저로 열면 한눈에 보입니다.

---

## 1. 캔버스 규격

| 항목 | 값 | 이유 |
|---|---|---|
| `viewBox` | `0 0 24 24` | 아이콘 표준 크기. 표 안에서 16~24px로 줄여도 뭉개지지 않습니다 |
| 안전 영역 | 상하좌우 **2px** | 좌표는 `2`~`22` 안에서만 씁니다. 가장자리에 붙으면 선이 잘립니다 |
| `stroke-width` | **2** (예외 없음) | 굵기가 섞이면 표에서 어떤 건 진하고 어떤 건 흐려 보입니다 |
| `stroke-linecap` / `linejoin` | `round` | 끝이 각지면 작은 크기에서 지저분해집니다 |
| `fill` | `none` | 면을 채우는 건 빼뜨기·반코 표시의 점뿐입니다 |
| `stroke` | `currentColor` | 글자색을 따라가므로 다크모드·PDF에서도 그대로 보입니다 |

`width`/`height`에 24를 적어두되 CSS로 덮어쓸 수 있게 했습니다. 색을 바꾸려면 부모의 `color`만 바꾸면 됩니다.

## 2. 모양 규칙

기호를 하나씩 따로 디자인하지 않고 **계열을 만들어 변형**합니다. 그래야 처음 보는 기호도 뜻을 짐작할 수 있습니다.

### 기둥 높이 = 빗금 개수

긴뜨기 계열은 **윗바 + 세로 기둥**이 공통 골격이고, 기둥을 가로지르는 빗금 개수로 높이를 구분합니다.

| 빗금 | 기법 |
|:---:|---|
| 0개 | `hdc` 긴뜨기 |
| 1개 | `dc` 한길긴뜨기 |
| 2개 | `tr` 두길긴뜨기 |
| 3개 | `dtr` 세길긴뜨기 |

빗금은 항상 `M8 …l8-4` 형태로 **왼쪽 아래 → 오른쪽 위** 방향이며 길이가 같습니다.

### 늘림은 V, 줄임은 Λ

편물에서 코가 퍼지는 방향을 그대로 그립니다.

- **늘림(V)** — 아래 한 코에서 위로 두 코가 벌어짐 → `inc`, `dc_inc`
- **줄임(Λ)** — 아래 여러 코가 위로 한 코에 모임 → `dec`, `sc3tog`, `dc2tog`, `dc3tog`
- **다리 개수** = 관여하는 코 수 (`sc3tog`·`dc3tog`는 다리 3개)
- **윗바가 있으면 한길긴뜨기 계열**, 없으면 짧은뜨기 계열

### 입체 무늬는 다발 모양

셋 다 한 코에 여러 번 떠서 부풀리는 기법이라 실제 도안에서도 비슷하게 생겼습니다. 이렇게 구분합니다.

| 기법 | 모양 |
|---|---|
| `puff` 퍼프 | 속이 보이는 다발 (윗바 없음) |
| `bobble` 구슬 | 다발 + 윗바 |
| `popcorn` 팝콘 | 닫힌 주머니 + 윗바 |

### 그 밖의 규칙

- **걸어뜨기** (`fpdc`/`bpdc`) — 한길긴뜨기 기둥의 아래쪽이 앞(오른쪽) 또는 뒤(왼쪽)로 휩니다
- **반코 표시** (`flo`/`blo`) — 가로선 두 줄이 코의 앞·뒤 반코이고, **점이 찍힌 쪽에 바늘을 넣습니다**
- **방향 전환** (`crab`) — 왼쪽 화살표로 진행 방향이 반대임을 나타냅니다
- **대바늘** — 겉뜨기 `|`, 안뜨기 `—`, 바늘비우기 `○`, 줄임은 기우는 방향대로 `/`(k2tog) `\`(ssk)

## 3. 새 기호를 추가할 때

1. `symbols/generate.py`의 `ICONS`에 `"코드": ("한국어 이름", [경로들])` 추가
2. 위 계열 규칙에 맞춰 좌표 작성 — **새 모양을 만들기보다 기존 계열의 변형을 우선**하세요
3. `python3 symbols/generate.py` 실행
4. `symbols/preview.svg`를 열어 다른 기호와 헷갈리지 않는지 확인
5. `craft_terms`에 기법을 추가하면 `thumbnail_url`은 자동으로 채워집니다 (아래 4번)

## 4. DB 연결과 화면 표시

`craft_terms.thumbnail_url`에 **`symbols/<standard_code>.svg`** 형태의 상대 경로가 들어갑니다.
`standard_code`로 규칙이 정해져 있어 SQL 한 줄로 전체를 채웁니다.

```sql
update craft_terms
set thumbnail_url = 'symbols/' || standard_code || '.svg'
where entry_type = 'stitch';
```

화면은 이 순서로 표시합니다.

```
thumbnail_url 이미지  →  symbol_icon 글자  →  '-'
```

`symbol_icon`에는 유니코드로 표현되는 8건(`○ ● × T Ŧ ◎ V Λ`)이 남아 있는데,
이미지가 우선이라 평소에는 쓰이지 않습니다. **이미지 로딩에 실패했을 때의 대비책**으로 두었습니다.

> 상대 경로를 쓰는 이유는 프론트엔드가 GitHub Pages에서, 아이콘도 같은 저장소에서 서빙되기 때문입니다.
> 도메인이 바뀌어도 경로를 고칠 필요가 없습니다. 외부 URL(`https://…`)을 넣으면 그대로 사용합니다.

- **용어사전 전용 4건**(배색·타원형 만들기·원형코 만들기·돗바늘 마무리)에는 기호가 없습니다.

- 기호는 **한국·일본식(JIS) 차트 표기**를 기준으로 그렸습니다. 미국식 차트는 표기가 다를 수 있습니다.
