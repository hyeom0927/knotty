# 기능 명세 & Gap 분석

현재 코드(`main.py` / `prompts.py` / `index.html`)를 기준으로 한 기능 목록입니다.
상태 표기: ✅ 동작 · 🟡 부분 구현·버그 있음 · ⬜ 미구현

---

## 1. 도안 생성 (Core)

| # | 기능 | 상태 | 현재 구현 / 부족한 점 |
|---|---|:---:|---|
| 1.1 | 유튜브 URL 입력 → 도안 표 생성 | ✅ | `POST /api/generate` |
| 1.2 | 영상 메타데이터 수집 (제목·설명란·채널명) | ✅ | 유튜브 워치 페이지를 직접 정규식 파싱 (`shortDescription`, `title`, `ownerChannelName`) |
| 1.3 | 채널 URL 수집 | ✅ | `"channelId":"UC…"` 우선 파싱 → `youtube.com/channel/{id}`. 실패 시 `canonicalBaseUrl`의 `@핸들`로 fallback |
| 1.4 | Creators 정보 수집 + 중복 방지 | ✅ | `channel_url` UNIQUE 기준 upsert(`on_conflict="channel_url"`). 1.3 복구로 정상 동작 |
| 1.5 | 자막 수집 | ✅ | Supadata API 우선, 실패 시 `youtube-transcript-api` fallback (로컬 전용) |
| 1.6 | 자막 없는 영상 예외 처리 | ✅ | 400 에러 + 사용자용 안내 문구 |
| 1.7 | AI 2-Pass 도안 추출 | ✅ | Pass 1 추출 → Pass 2 규격화 |
| 1.8 | 동일 URL 캐시 재사용 | ✅ | `youtube_url` 일치 시 DB 결과 즉시 반환 (`is_cached: true`) |
| 1.9 | 응답 JSON 방어 로직 | ✅ | 코드펜스 제거, 리스트 반환 시 딕셔너리로 보정, 정규식 fallback 파싱 |
| 1.10 | 기둥사슬 부연설명 자동 제거 | ✅ | `clean_pattern_text()` — "(코로 세지 않음)" 등 제거 |

## 2. 기법(Craft Terms)

| # | 기능 | 상태 | 현재 구현 / 부족한 점 |
|---|---|:---:|---|
| 2.1 | 도안에 쓰인 기법 목록 표시 | ✅ | 카탈로그(5분 캐싱)와 도안 JSON을 `standard_code` 정규식 매칭 |
| 2.2 | 기법별 참고 영상 링크 | ✅ | `video_url`이 없으면 링크 대신 `-` 표시. 원본 영상으로의 fallback 제거 |
| 2.3 | **기법은 항상 테이블을 참고하여 호출** | ✅ | `craft_terms` 전체를 Pass 2 시스템 프롬프트에 허용 약어 목록으로 주입 |
| 2.4 | 도안의 기법도 테이블 기준으로 통일 | ✅ | 2.3과 동일. 목록 밖 기법은 `formula` 대신 `unknown_terms`로 빠짐 |
| 2.5 | 신규 기법 자동 감지 → 테이블 추가 | ✅ | `unknown_terms` → `craft_terms_pending` 큐에 등장 횟수와 함께 누적 (⚠️ 테이블 생성 SQL 미실행) |
| 2.6 | 용어사전 페이지 (뜨개 용어) | ⬜ | 데이터(`craft_terms`)는 있으나 사전 화면이 없음 |

## 3. 검증 (Validation)

| # | 기능 | 상태 | 현재 구현 / 부족한 점 |
|---|---|:---:|---|
| 3.1 | 단별 코수 ↔ 도안 약어 일치 검증 | ✅ | `formula` 파싱 → 코수 합산 → `total_stitches`와 대조. 반복 그룹 `(…) x N`, 기둥사슬/기초사슬 구분, 매직링 처리 지원. 모르는 기법이 섞이면 `skipped` |
| 3.2 | 바늘 종류 = 코바늘 / 대바늘 | ✅ | 프롬프트 제약 + 서버의 `normalize_needle_type()` 보정 (표현이 모호하면 `formula`의 약어로 추론) |
| 3.3 | 총 단수(total_rows) 산출 | ✅ | Pass 2에서 "가장 단수가 많은 주요 파츠의 최대 단수"로 정의 |
| 3.4 | 검증 결과의 UI 노출 | ✅ | 문제 단은 행 강조 + ⚠️ 배지(사유 툴팁), 상단에 "확인이 필요한 단 N개" 배너. 자동 교정은 하지 않음 |
| 3.5 | 단 간 연속성 검사 | ✅ | 늘림·줄임이 없는데 앞 단과 코수가 달라지면 경고. 틀린 단은 기준선에서 제외해 연쇄 오탐 방지 |

## 6. 운영

| # | 기능 | 상태 | 현재 구현 / 부족한 점 |
|---|---|:---:|---|
| 6.1 | GitHub + Render + Supabase 운영 | ✅ | 노트의 "정식 출시가 아니라 GitHub로 진행" 항목은 이미 충족 |
| 6.2 | 오류 보고 기능 | ⬜ | 도안 카드에 "이 도안 이상해요" 버튼 → `reports` 테이블. 도안 30개 규모라면 **간단한 신고 폼 + Supabase 테이블이면 충분** (별도 에러 트래킹 SaaS 불필요) |
| 6.3 | API 남용 방지 | ⬜ | CORS `*` + 인증 없음 → 외부에서 `/api/generate`를 직접 호출하면 Gemini 비용이 그대로 발생 |
| 6.4 | 도안 수정 권한 | ⬜ | `PUT /api/pattern/{id}`에 인증이 없어 누구나 남의 도안을 덮어쓸 수 있음 |
| 6.5 | 의존성 정리 | ⬜ | `requirements.txt`에 streamlit·altair·pandas·pyarrow·numpy 등 미사용 패키지 다수 → Render 빌드 시간 낭비 |
